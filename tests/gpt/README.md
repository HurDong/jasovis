# ChatGPT 응답 일괄 입력 검증

```powershell
node --test tests/gpt/protocol.test.cjs tests/gpt/background.test.cjs tests/chat-tools/main.test.cjs
node tests/gpt/browser.cjs
# 질문 앞 번호가 붙은 지원서로 같은 MV3 시나리오 실행
$env:JSL_GPT_NUMBERED='1'
node tests/gpt/browser.cjs
Remove-Item Env:JSL_GPT_NUMBERED
# 단위 없는 분량·띄어쓰기·중첩 예시 생략 재현
$env:JSL_GPT_DETAILED='1'
node tests/gpt/browser.cjs
Remove-Item Env:JSL_GPT_DETAILED
```

브라우저 검증에는 Node에서 찾을 수 있는 `playwright`와 해당 Chromium이 필요합니다.
공용 패키지를 쓰면 `NODE_PATH`에 그 `node_modules` 경로를 지정합니다.

## 자동 검증

- `protocol.test.cjs`: 자연스러운 전략·표·다섯 문항 응답, 일부/역순/수정안, 번호 없는 블록,
  Codex 지시문, 질문 표시 차이와 의미 차이, 양쪽 질문의 번호 접두사·번호 충돌·소수/연도/본문 숫자 보존,
  접두사 제거 후 중복 질문, 중복·충돌의 수동 대응, 원문 보존, 문항/답변 변경, 대화 ID 분리.
- `background.test.cjs`: 일회용 준비 토큰, 준비 이후 사용자 수정, 연결/응답/탭/문서 변경,
  되돌리기(입력 직전 복원, 일회용 토큰, 직접 고친 문항 유지, 연결·응답·문서·대상 변경 거부),
  중복 탭, 다른 응답·대화의 동시 입력과 처리 중 연결 변경, 발신 출처/프레임, 연결 메타데이터의 저장 범위.
- `browser.cjs`: 별도 임시 프로필에 실제 MV3 확장을 로드하고 두 HTTPS 출처를 로컬 fixture로 대체.
  자연 응답 → 최초 지원서 선택 → 준비 → 실제 service worker/content script 메시지 → Angular 모델 입력 → 재조회 흐름을 검사.
  언어 미지정/css/yaml/text, 중첩 pre, 제목·공백·줄바꿈 보존, 응답 폭 정렬과 390px 가로 초과 없음,
  부분/역순 수정, 재로드 후 연결, 충돌/중복 선택, 선택 중 응답 변경 거부, 스트리밍/재생성, 기존 복사 버튼,
  중복/부재 탭, 훅 실패·후처리 불일치, 문항 변경, SPA 대화 분리, 연결 변경/해제, 저장 미호출을 확인.
- 기존 채팅 도구 테스트도 함께 실행해 인접 기능의 회귀를 확인한다.

fixture 문항·답변은 가상 데이터다. 브라우저 테스트는 실제 자소설닷컴 지원서에 입력하거나 저장하지 않는다.
입력 결과는 fixture 모델 재조회이며 실사이트 서버 저장 검증을 뜻하지 않는다.

## 실제 사이트 읽기 확인 — 2026-09-10

열려 있는 ChatGPT 대화에서 첫 자연 응답의 다섯 문항, 문항 원문/글자 수/소재/전략 목록,
중첩 `pre` 안의 단일 `code`, `code` 텍스트의 줄바꿈, `section[data-testid^="conversation-turn-"]`,
완료 응답 복사 버튼, markdown 부모의 폭을 읽기 전용으로 확인했다.
실제 지원서 질문에는 `(200자)`, `(500자)` 같은 끝의 분량 표기가 있음을 확인했다.
이 구조를 가상 데이터 fixture에 반영했다. 실제 사용자 답변은 테스트 파일에 보관하지 않는다.

2026-09-10 검증 당시의 브라우저 도구에서는 `chrome://extensions` 탭을 조작할 수 없어 설치된 확장을 다시 로드하지 않았다.
따라서 그 검증에는 변경 후 실사이트 버튼 표시/위치, 실제 지원서 입력·저장 및 사이트 자체 자동 저장 확인이 포함되지 않았다.
확장을 다시 로드하고 두 사이트 페이지를 새로고침하면 새 기능을 사용할 수 있다.

### 질문 앞 번호 대응 검증 — 2026-09-11

- 자동 검사 31개 통과. 일치하는 번호 접두사, 번호 충돌, 본문 숫자 보존, 중복 질문과 원문 보존을 확인했다.
- 기본 지원서와 `JSL_GPT_NUMBERED=1` 지원서에서 MV3 브라우저 시나리오를 각각 통과했다.
  최초 연결·다섯 문항 입력·되돌리기·부분 수정·충돌 선택·재조회·저장 미호출을 가상 데이터로 검증했다.
- 이전 UI 문구 `연결: 예시기업 ICT 55`를 찾던 테스트를 현재 연결 제목 표시에 맞췄다.
- 변경 후 설치된 확장 재로드와 실사이트 재적용은 수행하지 않았다.

### 작성 지침 축약 대응 검증 — 2026-09-11

- 실사이트 읽기에서 단위 없는 최소/최대, `서술해 주세요`의 공백, 중첩 예시 생략 차이를 확인했다.
- 가상 문항으로 재현한 자동 검사 32개 통과. 본 질문/지침 변경, 번호 충돌, 중복 대상, 필수 조건 생략은 보류한다.
- 기본·번호 접두사·작성 지침 축약 세 모드에서 전체 MV3 브라우저 시나리오 통과.
- 사용자 원문 답변은 fixture에 보관하지 않았고 실사이트 입력·저장은 수행하지 않았다. 설치된 확장 재로드 후 실제 적용은 미검증이다.

## 남은 경계

### 적용 문항으로 이동 — 2026-09-12

- 자동 검사 32개 통과. 실제 MV3 fixture에서 단일 2번 및 역순 다중 입력의 첫 문항으로 전환하고 표시 답변을 확인했다.
- 문항 전환 실패·질문 변경 시 오류 안내와 답변 보존을 검증한다. 탭/다른 창 활성화와 저장 미호출도 검사한다.
- 별도 `codex/gpt-review-question` 작업 트리에서 검증했다. 설치된 확장 변경과 실사이트 검증은 수행하지 않았다.
- 이후 사용자 요청으로 기존 작업 폴더에 이번 변경만 반영하고 자동 검사 32개와 MV3 브라우저 시나리오를 다시 통과했다. Chrome 확장 리로드 및 실사이트 적용은 미실행이다.
- 이후 사용자가 “오케이 잘된다”로 적용 후 해당 문항 이동의 실사이트 동작을 확인했다. 다른 예외 경로와 서버 저장 검증으로 확대하지 않는다.

사이트 DOM이 바뀌거나 문항과 코드 블록의 관계가 드러나지 않으면 버튼을 표시하지 않을 수 있다.
질문 문구/띄어쓰기가 실제로 다르거나 후보가 모호하면 선택 화면이 필요하다.
연결은 프로젝트가 아닌 대화 ID 기준이며, 대화 ID 없는 새/임시/공유 화면은 자동 연결하지 않는다.
준비 도중 작업자가 재시작되거나 90초가 지나면 다시 적용해야 한다.
저장 버튼을 호출하지 않지만 사이트의 기존 입력 훅이 수행하는 자동 저장까지 차단하는 기능은 아니다.
