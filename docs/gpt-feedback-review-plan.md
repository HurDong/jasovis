# GPT 질문 바 기획안 — 고른 곳 하나에 질문 하나

작성: 2026-09-15 (2026-09-14 인용 여러 개·대시보드 화면 안을 대체). 상태: `claude/gpt-feedback-review`에서 구현, 가상 페이지 기준 검증.

## 왜 바꿨나

2026-09-15 실사이트에서 한 바퀴 써 보고 다음이 걸렸다.

- 실제로는 거의 **한 곳에 한 번** 묻는다(1~3곳, 대부분 1곳). 인용을 모으는 목록·번호·모두 받기는 쓰이지 않고 화면만 복잡하게 했다.
- 담기 → 대시보드 맨 아래 **GPT 질문** 버튼 → 화면 이동 → 메모 → 보내기로 동선이 길고, 진입 버튼이 아래에 묻혀 있었다.
- 빠진 맥락·AI 티를 고르는 버블은 결국 매번 같은 고민이라, 사용자는 **직접 쓰는 질문**에 집중하고 두 가지는 GPT가 알아서 봐야 한다.
- 보낸 뒤 GPT 탭으로 옮겨가 기다렸다가 돌아오는 흐름은 불편했다.

## 목표

1. 드래그하거나 `Shift`+방향키로 고르면 **우클릭 없이** 그 자리에 질문 바가 뜬다. `Alt+Q`면 곧바로 질문 칸에 커서가 있다.
2. 질문은 한 줄~여러 줄 직접 쓰고 `Enter`로 보낸다. 비워 보내도 된다. 빠진 맥락·AI 같은 표현 점검은 기본 지시로 항상 들어간다.
3. 보내도 탭을 옮기지 않는다. 쓰던 자리로 커서가 돌아오고, 같은 자리의 작은 표시가 진행을 알려 준다.
4. 답이 오면 **같은 자리**에 원문 → 수정안이 뜨고 `바꾸기` 한 번으로 끝난다. 되돌리기는 잠시 남는다.
5. 떠 있는 UI는 고른 줄과 대시보드를 가리지 않는 자리를 먼저 찾는다(공고 왼쪽 + 대시보드 오른쪽 배치 고려).
6. 자동 반영·자동 저장은 없다. 바꾸기는 누를 때만, 저장은 사용자가 직접.

## 흐름과 상태

```
고르기 ──► offer 바 ──(클릭·Alt+Q)──► compose 칸 ──Enter──► 보내는 중
                                           │                   │
                                  Esc(고른 곳 복원)      blocked: 칸에 이유, 글 유지
                                                               │
                                                  waiting 알약 ◄┘ (sent)      unknown 카드 (확인 불가)
                                                        │
                                               result 카드 ⇄ arrived 알약(접기/보기)
                                                        │
                                  바꾸기 ──► applied 알약(되돌리기, 8초) ──► 끝
                                  버리기/닫기 ──► 끝
```

- 다른 문항에 있으면 `elsewhere` 알약 `N번 문항 질문 · GPT가 고치는 중|답 도착 · 가기`를 답변란 오른쪽 위에 붙인다.
- GPT 탭이 닫히면 `GPT 탭이 닫혔어요 · 다시 열기 · 취소`. 다시 열면 같은 요청의 답을 이어서 기다린다.
- 질문 칸은 탭마다 하나. 새 질문이 GPT로 가면(sent/unknown) 이전 질문 기록을 지운다. 막힌 전송(blocked)은 이전 질문을 건드리지 않는다.

## 화면 문구

| 상태 | 문구 |
|---|---|
| offer | `✦ 이 부분 GPT에게 질문` `Alt+Q` |
| compose | 인용 한 줄 · placeholder `무엇이 아쉬운지, 어떻게 바꾸고 싶은지 적어 주세요` · `→ 대화 제목 ▾` · `↵ 보내기 · Shift+↵ 줄바꿈` · `보내기` |
| compose 안내 | `보낼 GPT 대화를 골라 주세요` / `보내지 못했어요 · 이유` / `고른 곳이 바뀌었어요…` / `보내면 앞서 보낸 질문은 닫혀요.` |
| waiting | `GPT가 고치는 중 · 12초`(쓰기 시작하면 `GPT가 답을 쓰는 중`) · 45초 무진행이면 `GPT 탭 보기` · `취소` |
| result ready | `수정안 +18자 · 접기` / `내 질문 · …` / 진단 / 원문(취소선) → 수정안 / `확인 · …` / `버리기 · GPT에서 보기 · 바꾸기 ↵` |
| result 기타 | `GPT 답`(답만), `확인이 필요해요`(`GPT에서 답하기`), `바꿀 곳이 없대요`, `답을 읽지 못했어요`, `원문이 바뀌어 넣지 못했어요`(`수정안 복사`) |
| unknown | `보냈는지 확인하지 못했어요` · `GPT에서 확인 · 보냈어요 · 답 기다리기 · 다시 보내기` |
| applied | `✓ 바꿨어요 · 되돌리기` (title: 사이트의 저장은 직접 눌러 주세요) |

색은 주황 `#ff6a00` + 무채색만, 버튼은 플랫 단색. 기존 대시보드 버튼(`GPT 질문`)과 대시보드 기능 화면 API는 없앴다.

## 자리 찾기

`JSLFeedbackMarks.measure(start, end)`가 답변란 글꼴·여백을 복제해 고른 곳의 줄 사각형을 돌려준다.

- 큰 칸(compose·result·unknown): 답변란 **오른쪽 → 왼쪽 → 고른 줄 위 → 아래**.
  옆자리가 300px 이상이면 칸 폭을 그 자리에 맞춰 줄인다(질문 칸 최대 380px, 수정안 400px).
- 작은 바·알약(offer·waiting·arrived·applied): **위 → 아래 → 오른쪽 → 왼쪽**.
- 후보는 화면 안이면서 고른 줄·대시보드(`#jsl-dashboard .wrap`)와 겹치지 않아야 한다. 한 번 고른 쪽을 먼저 다시 본다(쓰는 동안 튀지 않게).
- 모두 안 되면 위·아래 중 넓은 쪽에 붙이고 최대 높이를 줄여 칸 안에서 스크롤한다.
- 고른 곳이 답변란 밖으로 스크롤되면 offer는 숨기고 상태는 답변란 오른쪽 위에 붙인다. 답변란이 다른 요소(맞춤법 패널 등)에 가려지면 숨긴다(쓰는 중인 칸 제외).
- 스크롤·크기 변경·입력 때와 300ms마다 다시 잰다.

## 요청 형식

````
[자비스 요청] 자소설닷컴 N번 문항 답변에 대한 질문입니다.
이 대화에 있는 공고·이력·다른 문항 정보를 근거로 삼아 주세요.

문항 N: <문항 질문>

고칠 부분: <고른 글>
주변 문맥: <같은 문단 앞뒤 160자, 고른 글과 같으면 생략>
질문: <사용자 질문 | 따로 없음. 아래 규칙대로 다듬어 주세요.>

규칙
- 질문에 답하면서, 고칠 부분에 빠진 맥락(어디서·무엇을·왜)이나 AI가 쓴 듯한 상투적·번역투 표현이 있으면 함께 고칩니다.
- 대화에 없는 소속·경험·기간·수치는 지어내지 않습니다. 근거가 부족하면 "확인 필요"에 무엇을 알려주면 되는지 적습니다.
- 수정안 코드 블록에는 고칠 부분 자리에 그대로 넣을 문장만 적습니다. 고칠 부분 밖 문장은 고치지 않습니다. 고칠 필요가 없으면 수정안을 쓰지 않습니다.
- 아래 형식만 사용합니다.

진단: …
수정안:
```
…
```
확인 필요: 없음
````

내부 ID·revision·요청 ID는 보내지 않는다. 첫 줄은 보낸 메시지를 찾는 기준이자 기존 적용 패널을 붙이지 않는 표지다.

## 판독

`parseAnswer(blocks, quoteText)` — 보낸 메시지 바로 다음 assistant 답의 블록 전체를 한 구간으로 읽는다.

- 코드 블록 1개 → 수정안. 앞뒤 공백은 고른 글 기준. 같으면 `same`.
- 코드 없음 + 확인 필요 → `ask`, 코드 없음 + 진단만 → `note`(질문에 답만 한 경우).
- 코드 2개 이상·빈 수정안·8,000자 초과·틀 문구(`수정안:`, 백틱)·아무 형식 없음 → `invalid`.

## 바꾸기·되돌리기

- 질문한 문항이 활성이고 모델 답변과 입력란이 같을 때만. `locate(현재 입력란, 고른 글, 보낸 위치)`가 확정한 자리만 바꾼다.
- 못 찾으면 `stale` 기록 후 쓰지 않고 수정안 복사를 준다.
- 쓰기는 `setAnswer`, 모델·입력란이 기대값과 같아질 때까지 확인한 뒤 입력 이벤트로 검수 마커 층을 갱신한다.
- `applied{at, replacement, original}`을 워커에 기록(받은 수정안·고른 글과 같을 때만 받음). 8초 뒤 알약을 닫고 기록을 지운다.
- 되돌리기는 바꾼 글을 같은 방식으로 찾을 때만 원문으로 되돌린다. 사용자가 바꾼 곳을 직접 고치면 되돌리기를 거둔다.

## 전송과 뒤 탭

- 대화 탭이 없으면 `active:false`로 연다. 먼저 뒤 탭에 그대로 넣고 보낸다(`background:true`).
- 뒤 탭에서 입력이 반영되지 않거나 전송 버튼이 켜지지 않으면(클릭 승인 전, 사용자 편집 없음) 클라이언트가 넣은 글을 지우고 `retry`를 돌려준다.
  워커는 그때만 GPT 탭을 잠깐 앞으로 가져와 한 번 더 넣고, 끝나면 곧바로 자소설 탭으로 돌아온다.
- 뒤로 간 ChatGPT 탭이 답을 끝까지 그리지 않은 사례가 있었다(2026-09-15 실사이트). 원인을 보이지 않는 탭의 `requestAnimationFrame` 멈춤으로 보고(실사이트 확인 전), 전달·감시 중에만
  `<html data-jsl-keep-rendering>`을 켜고, MAIN 스크립트 `gpt-render-main.js`가 숨은 탭의 프레임 요청을 타이머로 돌린다.
- 확인 불가는 자동 재전송하지 않는다. `보냈어요 · 답 기다리기`는 첫 줄로 메시지를 찾아 이어받고, `다시 보내기`는 질문 칸을 되살린다.

## 메시지

| type | 방향 | 내용 |
|---|---|---|
| `feedback:load` | 자소설 → 워커 | 이 탭의 질문 칸 요약(같은 지원서일 때) + 대화 후보 |
| `feedback:targets` / `select` | 자소설 → 워커 | 대화 후보 / 연결 선택 |
| `feedback:send` | 자소설 → 워커 | `{ask, conversation, attempt}` → `sent/unknown/blocked` |
| `feedback:deliver` | 워커 → GPT | `{prompt, background}` → `sent{messageId}` / `blocked{retry?}` / `unknown` |
| `feedback:authorize` | GPT → 워커 | 클릭 직전 재검증, `committing` 기록 |
| `feedback:reply` | GPT → 워커 | `{attempt, messageId, phase, blocks}` |
| `feedback:watch` / `locate` / `start-watch` | GPT ↔ 워커 | 새로고침 뒤 감시 재개 / 확인 불가 이어받기 |
| `feedback:changed` | 워커 → 자소설 | 다시 불러오라는 신호 |
| `feedback:review` | 자소설 → 워커 | 바꾼 기록 `applied` / `stale` / `null` |
| `feedback:claim` / `focus` / `dismiss` | 자소설 → 워커 | 이어받기 / GPT 탭 앞으로 / 질문 끝 |

## 경우의 수

| 상황 | 동작 |
|---|---|
| 복사하려고 드래그 | 바가 뜨지만 커서는 답변란에 그대로. 복사·계속 쓰기 가능, 밖을 누르면 닫힘 |
| 한글 조합 중·드래그 중 | 바를 띄우지 않음 |
| 질문 칸에 글이 있는데 답변란을 다시 누름 | 칸 유지. 새로 고르면 그 곳으로 바뀜 |
| 쓰는 사이 고른 글을 편집 | 유일하게 찾으면 따라감, 못 찾으면 `고른 곳이 바뀌었어요`로 막음 |
| 질문 칸에서 Ctrl+S·Alt+숫자 | 사이트 저장·문항 전환 안 함 |
| 대화 미선택 | 칸 안 목록을 열고 안내 |
| GPT 입력창에 작성 중인 글·첨부·답변 생성 중 | 보내지 않고 칸에 이유, 글 유지, 앞 질문 유지 |
| 뒤 탭 입력 미반영 | 넣은 글 지우고 잠깐 앞 탭으로 한 번 재시도 후 복귀 |
| 전송 확인 불가 | 자동 재전송 없음. 이어받기 / 다시 보내기 |
| 다른 문항으로 이동 | elsewhere 알약 + 가기 |
| 답변란이 화면 밖일 때 답 도착 | 토스트 `GPT 답 도착 · N번 문항` |
| 기다리는 사이 고른 글 편집 | 바꾸기 시 `원문이 바뀌어 넣지 못했어요` + 수정안 복사 |
| GPT 탭 닫힘 | lost 알약 + 다시 열기, 감시 재개 |
| 새로고침 | 질문·답·결정 복원. 끝난(applied) 기록은 정리. 쓰던 질문 칸 글은 사라짐 |
| 자소설 탭 닫힘 | 세션 기록 삭제 |

## 개인정보

세션에만 `feedback:slot:<탭>`과 `feedback:attempt:<요청>`(고른 글·위치·질문·메시지 ID·진행·판독 결과·바꾼 기록)을 둔다.
전송 전 검증을 위해 답변 전체를 잠시 들고 있다가 결과가 정해지면 지운다. 영구 저장은 기존 `feedback-chat:*`·`feedback-preferred:*`뿐이다.
