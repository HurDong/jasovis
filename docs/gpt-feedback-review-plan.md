# GPT 질문 → 제안 받기 기획안

작성: 2026-09-14. 상태: `claude/gpt-feedback-review` 워크트리에서 구현, 가상 페이지 기준 검증 완료(실사이트 미검증). 기준 커밋: `6e3d83a`.

## 1. 목표

자소설 편집 화면에서 **고칠 곳을 드래그해 모으고 → 연결된 웹 GPT에 한 번에 보내고 → 돌아온 수정안을 인용 단위로 받거나 빼는** 흐름을 자소설 화면 안에서 끝낸다.

사용자가 실제로 자주 묻는 것은 두 가지다.

- **빠진 맥락**: 프로젝트·활동 이름만 있고 어디서, 무엇을 위해 했는지 생략된 곳.
- **AI 티**: 상투적·번역투라 사람이 쓴 글 같지 않은 표현.

그 밖의 요청은 **질문**(한 줄 메모)으로 받는다. 톤 조절 버튼은 두지 않는다.

### 원칙

- 새 창을 띄우지 않는다. 대시보드 본문이 잠시 “GPT 질문” 화면으로 바뀐다. 공고(왼쪽)·대시보드(오른쪽) 배치를 그대로 둔다.
- 대시보드 토큰(크림 외피, 흰 카드, `#ff6a00` 주황, 번호 동그라미, 칩)만 쓴다. 단축키·미리보기 층·자동 문항 이동은 넣지 않는다.
- 반영은 **사용자가 받기를 누른 인용만**, 그 구간만 `setAnswer`로 바꾼다. 쓰기 직전에 원문을 다시 확인한다. 저장 버튼은 누르지 않는다.
- 부분 성공·확인 불가·실패를 성공처럼 보이지 않는다. GPT 탭의 구조를 못 읽으면 “GPT에서 보기”로 넘긴다.
- 별도 서버·OpenAI API는 쓰지 않는다. 연결된 웹 GPT 대화의 맥락(공고·이력)을 그대로 쓴다.

### 하지 않는 것

단축키, 답변란 위 전체 미리보기, 문항을 넘나드는 제안 큐, 인용당 여러 대안, 자소설 안에서 “확인 필요”에 답장(→ GPT 탭에서 답한다), 자동 저장.

## 2. 사용자 흐름

```
① 답변 드래그 → 버블 [빠진 맥락 | AI 티 | 질문]
② 대시보드 “GPT 질문” 화면에 인용 카드가 쌓임 (질문은 한 줄 메모 필수, 나머지는 선택)
③ [GPT로 보내기 · N] → GPT 탭에서 입력·전송 확인 → 자소설 탭으로 돌아옴
④ 답을 기다리는 동안: 상태 한 줄 + 경과 시간, 계속 편집 가능
⑤ 답 도착: 인용 카드가 제안 카드로 바뀜 (원문 → 수정안, 받기/빼기)
⑥ 받기: 그 구간만 교체 → 답변란에 “수정됨” 표시, 카드는 “받음 · 되돌리기”
⑦ 모두 처리하면 [새 질문]
```

## 3. 화면 상태와 문구

대시보드 헤더·진행 영역은 그대로 두고, 본문 위에 한 줄 머리를 둔다: `‹ 문항 | GPT 질문 | N번 문항`. 맨 아래 주황 버튼 자리는 평소와 같다.

| 상태 | 본문 | 맨 아래 |
|---|---|---|
| 비어 있음 | “답변에서 고칠 곳을 드래그해 담아 주세요.” | 주황 비활성 `고칠 곳을 담아 주세요` |
| 담는 중 | 인용 카드들 + `보낼 GPT 대화 제목 · 변경` | `GPT로 보내기 · N` / 이유가 있으면 비활성 문구 |
| 보내는 중 | 상태 `GPT 탭에서 보내는 중…` | 비활성 `보내는 중` |
| 기다리는 중 | 상태 `GPT가 답하는 중 · 인용 N개 · 1분 12초` + `GPT에서 보기 ↗`, 카드 흐리게 | 비활성 `답을 기다리는 중` |
| 답 도착 | 요약 `수정안 2 · 확인 필요 1` + 제안 카드 | `남은 N개 모두 받기` + `모두 빼기` |
| 모두 처리 | 요약 + 접힌 카드 | `새 질문` |

비활성 버튼 문구(우선순위 순): `질문 내용을 적어 주세요` → `원문이 바뀐 인용을 빼 주세요` → `보낼 GPT 대화를 골라 주세요` → `GPT로 보내기 · N`.

### 인용 카드 (담는 중)

`[번호] 원문 한 줄(말줄임) [종류 칩] ×` + 메모 한 줄 입력(질문은 필수 “무엇을 물어볼까요?”, 나머지는 “덧붙일 말 (선택)”). 원문을 못 찾게 된 인용은 `원문이 바뀌었어요 · 다시 담아 주세요` 경고와 × 만 남는다.

### 제안 카드 (V3)

한 흐름으로 `취소선 원문 → 수정안` + 오른쪽 `받기`, 아래 작은 줄에 진단과 `빼기`.

| 판정 | 카드 |
|---|---|
| 수정안 있음 | V3 카드. 확인 필요 문장이 함께 오면 진단 아래 표시 |
| 확인 필요만 | `?` 동그라미 + GPT의 질문 + `GPT에서 답하기 ↗` |
| 바꿀 곳 없음(수정안 = 원문) | `바꿀 곳이 없대요` + 진단 |
| 형식 오류 | `!` + `이 인용의 수정안을 찾지 못했어요` + `GPT에서 보기 ↗` |
| 원문 바뀜(받기 시점) | `!` + `원문이 바뀌어 넣지 않았어요` + `수정안 복사` |
| 받음 | `✓ 받음` 한 줄 + `되돌리기` |
| 뺌 | `뺌` 한 줄 + `다시 보기` |

### 버블

선택 영역 근처에 흰 알약 `[빠진 맥락 | AI 티 | 질문]`. 조합(IME) 중·선택 없음·스크롤·다른 곳 클릭이면 숨긴다. 같은 범위를 다시 담으면 기존 인용의 종류만 바꾼다. 기다리는 중·답 도착 상태에서는 담지 않고 토스트 `보낸 질문을 처리한 뒤 새로 담을 수 있어요`.

### 답변란 표시

답변란 위에 글자 투명·클릭 통과 층을 겹쳐 배경만 칠한다.

- 담은 인용(보내기 전·기다리는 중·받기 전): 주황 밑줄 + 오른쪽 위 작은 번호.
- 받은 구간: 연주황 배경 + 옅은 밑줄.
- 답변란이 가려졌거나(맞춤법 패널 등) 문항이 바뀌면 숨긴다. 원문을 고쳐 위치를 못 찾으면 그 표시만 지운다.

### 알림

- GPT 질문 화면이 닫혀 있을 때 답 도착: 토스트 `GPT 답 도착 · N번 문항` + `제안 보기`. 다른 문항이면 `N번 문항으로`. 대시보드 `GPT 질문` 버튼 라벨에 담은 수·`답 기다리는 중`·`제안 N`.
- 전송 결과 blocked: 상태 상자에 이유 그대로, 인용은 편집 가능하게 남김.
- 전송 결과 unknown: `보냈는지 확인하지 못했어요` + `GPT에서 확인 ↗` + `보내지 않았다면 다시 보내기`(새 요청 ID로만).

## 4. 요청 형식 (앱이 강제)

GPT 입력에는 내부 ID를 넣지 않는다. 첫 줄 표지 `[자비스 요청]`은 응답 판별과 기존 “자소설에 적용” 패널 제외에만 쓴다.

````
[자비스 요청] 자소설닷컴 2번 문항 답변에서 고칠 곳 2개입니다.
이 대화에 있는 공고·이력·다른 문항 정보를 근거로 삼아 주세요.

문항 2: 지원 직무 역량을 쌓기 위해 노력한 경험을 기술하세요.

규칙
- 대화에 없는 소속·경험·기간·수치는 지어내지 않습니다. 근거가 부족하면 수정안 대신 "확인 필요"에 무엇을 알려주면 되는지 적습니다.
- 수정안 코드 블록에는 원문 인용 자리에 그대로 넣을 문장만 적습니다. 인용 밖 문장은 고치지 않습니다.
- 인용마다 아래 형식만 사용합니다.

### 인용 N
진단: 한두 문장
수정안:
```
원문 인용을 대체할 문장
```
확인 필요: 없음

[인용 1 · 빠진 맥락]
원문: JobFit 프로젝트에서
주변 문맥: …
요청: 무엇을 어디서, 무엇을 위해 했는지 등 빠진 맥락을 채워 주세요.
덧붙임: 캡스톤 프로젝트였어

[인용 2 · AI 티]
원문: …
요청: 뜻과 사실은 유지하고, 상투적이거나 번역투인 표현을 실제 지원자가 쓸 법한 담백한 문장으로 바꿔 주세요.
````

## 5. 응답 판독

GPT 탭은 **전송 확인 때 잡은 내 메시지 ID 바로 다음 assistant 메시지**만 읽는다. 완료 기준은 기존 적용 패널과 같다(스트리밍 표시 없음 + 턴 복사 버튼 존재).

블록(제목/문단/코드/경계)을 인용 구간으로 나눈다.

- 구간 시작: `인용 N` 제목(h1~h6) 또는 `인용 N`으로 시작하는 짧은 문단(`**인용 1**`, `[인용 1]`, `인용 1 —` 허용).
- 구간 안 코드 블록 1개 = 수정안(앞뒤 줄바꿈만 정리). 2개 이상이면 형식 오류.
- `진단:` 문단 = 진단. `확인 필요:` 문단에서 `없음/없습니다/-`가 아니면 확인 필요.
- 수정안이 비었거나 8,000자를 넘거나 `인용 \d`·`수정안:` 같은 틀 문구가 섞이면 형식 오류.
- 요청한 인용이 빠졌거나 두 번 나오면 그 인용만 형식 오류. 요청하지 않은 번호는 무시.

## 6. 반영·되돌리기

반영은 자소설 탭에서만 하고, 그 문항이 활성일 때만 한다.

1. 현재 답변(모델 값과 입력란 값이 같아야 함)을 읽는다.
2. 인용 위치 찾기: 기록 위치(앞서 받은 인용의 길이 변화만큼 보정)의 원문이 같으면 그 자리, 아니면 원문이 답변에 **정확히 한 번** 있을 때만 그 자리. 아니면 “원문 바뀜”.
3. 교체한 전체 문자열을 `setAnswer`로 쓰고, 재조회해 기대값과 같을 때만 “받음”.
4. 되돌리기: 받은 수정안을 같은 방식으로 찾아 원문으로 바꾼다. 못 찾으면 `직접 고친 곳이라 되돌리지 않았어요`.
5. `모두 받기`는 앞에서부터 차례로 같은 절차를 밟고, 실패한 인용은 그 카드에만 표시한다.

### 메시지

| 메시지 | 방향 | 내용 |
|---|---|---|
| `feedback:load` | 자소설 → 워커 | 초안 + 전송 기록(상태·경과·판독 결과) + 대화 후보 |
| `feedback:save` / `targets` / `select` | 자소설 → 워커 | 기존과 같음 |
| `feedback:send` | 자소설 → 워커 | 전송. 성공 시 `userMessage` 보관, 자소설 탭 다시 활성화 |
| `feedback:reply` | GPT → 워커 | `{attempt, messageId, phase: streaming/complete, blocks?, seen}` |
| `feedback:watch` | GPT → 워커 | 이 대화에서 답을 기다리는 요청 목록(새로고침 후 재개) |
| `feedback:changed` | 워커 → 자소설 | 다시 불러오라는 신호 + 완료 여부·문항 번호(다른 문항 알림용) |
| `feedback:focus` | 자소설 → 워커 | 연결된 GPT 탭 앞으로 |
| `feedback:dismiss` | 자소설 → 워커 | 끝난 요청 정리(새 질문) |

## 8. 경계 사례

| 사례 | 처리 |
|---|---|
| 담은 뒤 답변을 계속 편집 | 인용마다 위치를 다시 찾음. 못 찾은 인용만 경고, 나머지는 보낼 수 있음 |
| 같은 문구가 여러 번 있는 곳을 담은 뒤 앞부분 편집 | 기록 위치가 어긋나고 중복이면 “원문 바뀜” (추측하지 않음) |
| 문항 전환 | 문항별 초안·요청이 따로 유지. 화면은 현재 문항 것만 |
| 자소설 새로고침 | 세션에서 초안·요청·판독 결과 복원 |
| GPT 탭 새로고침/대화 이동 후 복귀 | 감시 재개(`feedback:watch`) |
| GPT 탭 닫힘 | 기다리는 요청에 `GPT 탭을 찾을 수 없어요 · 다시 열기` |
| GPT 답이 형식 무시 | 인용별 형식 오류 + GPT에서 보기 |
| 답 재생성·수정 | 완료 판독 이후 바뀐 응답은 다시 읽지 않음(이미 받은 반영 보호) |
| 전송 blocked/unknown | 3장 알림 규칙 |
| 워커 재시작 | 기록은 세션. GPT 탭 감시자가 다음 메시지로 워커를 깨움 |
| 확장 다시 로드 | 세션·콘텐츠 스크립트가 끊김 → 기존 안내(페이지 새로고침) |
| 원본 자소설 탭 닫힘 | 초안·요청·판독 결과 삭제 |
| 다른 지원서 탭에서 같은 GPT 대화로 보냄 | 기존 연결 계약(다른 지원서 대화 제외) |

## 9. 개인정보

추가로 세션에 보관: 요청 인용(원문·종류·메모), 전송 메시지 ID, 판독한 진단·수정안·확인 필요 문장. 원본 탭을 닫거나 브라우저·확장을 재시작하면 삭제. 영구 저장 없음. PRIVACY.md에 반영.

## 10. 검증

- 단위: 초안 v2·재배치·요청 문구·판독(정상/굵은 제목/형식 오류/누락/중복/여러 코드블록/확인 필요/바꿀 곳 없음)·위치 찾기·교체·되돌리기.
- 워커: 전송 후 메시지 ID 보관, 응답 수신 발신자 검증, 판독 보관, 감시 목록, 탭 닫힘 표시, 정리.
- 브라우저(가상 자소설 + 가상 GPT, 실제 MV3): 버블 3종 → 대시보드 화면 → 보내기 → 가상 GPT가 형식 답 생성(스트리밍 흉내) → 도착 → 받기(답변 교체·표시) → 되돌리기 → 모두 받기 → 형식 오류 인용 → 원문 바뀜 → 새로고침 복원 → 적용 패널 미부착 → 저장 미호출.
- 실사이트: 실제 ChatGPT DOM에서 응답 판독과 뒤 탭 완료 감지는 **미검증**. 사용자 허락 범위에서 따로 확인한다.
